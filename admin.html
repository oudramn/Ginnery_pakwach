How it works

One message, a thoughtful audience.

  1. Only unique addresses from enquiries with an explicit marketing opt-in are included.
  2. Older enquiries without a recorded opt-in are left out.
  3. Guests are grouped into small BCC batches to keep each email private and reliable.
  4. Record an opt-out below. Suppressed addresses stay out of every campaign.

The dashboard does not send or track email delivery. Your email provider handles sending.

Role guide

Administrator

Full dashboard access, including account search, account creation, role changes and deactivation. The admin role cannot be assigned or changed here.

Manager

Reservations, reports, offers and website editing. Cannot view or manage staff accounts or administrator privileges.

Website Manager

Explore page, hotel journal, photos, menu, events, anonymous visitor and enquiry-conversion metrics, and post attention. Cannot access reservations, sales, users or administrator controls.

Staff

Overview and reservation follow-up. Cannot publish website content or access account management.

Administrator controls

Security & records.

Server-side audit history, local database backups and an optional automatic retention period for reservation requests.

Guest request retention

Admin only
When enabled, expired requests are removed daily. Choose a period approved for the hotel’s legal and privacy requirements.
Enter any whole number from 1 to 3650. Use 0 for no automatic expiry. Records older than this period are removed during retention checks. The erase button below clears all existing audit records immediately.

Database backups

Local server

Daily local snapshot. In AWS production, a KMS-encrypted copy is also sent to private S3 storage.

Erase removes every local backup, all configured off-site backup versions and all audit history. The audit retention period remains configured for future entries.

Secure payments

No card or mobile money payment provider is configured. Select a PCI-compliant provider, merchant account, webhook URL and live/test credentials before enabling checkout. This app does not collect or store card data.

PMS / booking engine

No property-management or channel system is configured. Connection requires the hotel’s chosen vendor, API access, room/rate mapping, booking rules and duplicate-prevention strategy.

Deployment security

This deployment uses one EC2 instance and SQLite. Add MFA or SSO, centralized monitoring, restore drills and a security review before handling real guest data.

This system stores records server-side with staff authentication, role authorization, audit logs, backups and configurable data retention. Live payments and PMS/booking-engine synchronization need provider selection, merchant/API credentials and owner-approved booking rules. Production deployment still requires operational review.
